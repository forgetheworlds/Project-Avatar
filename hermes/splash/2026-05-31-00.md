### Benchmark Data (MacBook M3, 10-core GPU, MPS acceleration)

| Model | YOLOv12 FPS | YOLOv13 FPS | Use Case |
|-------|-------------|-------------|----------|
| Nano (N) | **85-110 FPS** | Similar range | Real-time CV pipeline target |
| Small (S) | **55-70 FPS** | Similar range | High-accuracy tracking |
| Medium (M) | 35-45 FPS | Similar range | Analytics/crowd mapping |
| Large (L) | 20-30 FPS | Similar range | High-precision counting |

### Key Architectural Differences
- **YOLOv12**: Attention-centric with Area Attention (A²) module + FlashAttention for memory efficiency. Breaks from pure CNN design — captures global context without transformer latency.
- **YOLOv13**: Hypergraph-enhanced with "HyperACE" mechanism. Up to 18% improvement in false-negative rates under dynamic conditions (occluded/overlapping persons). Better for Splash's target tracking through obstacles.

### Recommendation for Splash
- **YOLOv12n** as primary detector: 85-110 FPS is more than enough for the pipeline target (<50ms total). This frees CPU/GPU for ByteTrack + Kalman + servo PID on the same MacBook.
- **YOLOv13n** if occlusion handling becomes an issue — the 18% FN reduction helps when target passes behind columns/walls.
- **MPS acceleration**: Use `device="mps"` in PyTorch. No CUDA dependency needed on MacBook M3.
- **Previous Cycle 2 estimate**: YOLOv11n at 75-80 FPS. v12n represents a 10-35% improvement.

## 4. 🟢 ARDUPILOT SERVO GIMBAL AUTO-TRACKING CONFIGURATION

Complete parameter set for Splash's pan-tilt water gun:

### Step 1: Enable Servo Gimbal
```
MNT1_TYPE = 1    # Servo gimbal (reboot required)
```

### Step 2: Map Servo Outputs (MicoAir H743 PWM groups)
```
SERVO5_FUNCTION = 8    # PWM5 = Mount1 Pitch (tilt) [was 6 in earlier config]
SERVO6_FUNCTION = 9    # PWM6 = Mount1 Yaw (pan)   [was 7 in earlier config]
```

### Step 3: Configure Tracking Mode
```
MNT1_DEFLT_MODE = 3    # GPS Point tracking (track a coordinate)
MNT1_RC_RATE = 0       # Absolute angle mode for RC override
```

### Step 4: Manual RC Override (for testing/pilot control)
```
RC6_OPTION = 213   # CH6 = Mount1 Pitch manual override
RC7_OPTION = 214   # CH7 = Mount1 Yaw manual override
```

### Step 5: Pump Servo/MOSFET (Sprayer)
```
SERVO7_FUNCTION = 22   # Sprayer Pump (PWM7)
```

### Auto-Tracking Logic
- **Auto mode**: When in AUTO or GUIDED mode, gimbal tracks specified GPS point (DO_SET_ROI)
- **RC override**: Moving mapped RC channels (CH6/CH7) > deadzone temporarily switches to manual control
- **Auto-return**: After RC input stops + timeout, snaps back to tracking target
- **Splash CV integration**: MacBook sends RC_CHANNELS_OVERRIDE MAVLink commands to point gimbal at CV-detected target, overriding the GPS tracking mode in flight

### Correction from Cycle 2 Config
Previous config used SERVO5_FUNCTION=6 (Mount Yaw) and SERVO7_FUNCTION=7 (Mount Pitch). Correct ArduPilot mapping for a 2-axis pan-tilt:
- SERVO5_FUNCTION=8 (Mount1 Pitch - vertical tilt)
- SERVO6_FUNCTION=9 (Mount1 Yaw - horizontal pan)
These are the standard Mount1 functions. Previous research used Mount1 Roll (7) and Mount1 Pitch (8) incorrectly.
