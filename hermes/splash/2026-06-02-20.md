## §1. 🟢 NEW: Protection Mode Module

### Architecture

```
Main State Machine (ORBITING state)
              │
              ▼
   ProtectionMode (sub-state machine)
   ┌────────────────────────────────────┐
   │  SCANNING → DETECTED → ENGAGING   │
   │        → RETURNING_TO_ORBIT       │
   │        → ABORTED (battery crit)   │
   └────────────────────────────────────┘
              │
              ▼
   Callbacks: on_fire, on_aim, on_orbit_resume,
              on_return_to_orbit, on_abort
```

### Sub-States

| Sub-State | Description | Transitions To |
|-----------|-------------|----------------|
| IDLE | Not active | SCANNING (via start()) |
| SCANNING | Orbiting, watching for intruders | DETECTED, ABORTED |
| DETECTED | Target identified, moving to engage | ENGAGING, RETURNING_TO_ORBIT, ABORTED |
| ENGAGING | Tracking + aiming + firing | RETURNING_TO_ORBIT, ENGAGE_WAITING, ABORTED |
| ENGAGE_WAITING | Target lost, waiting for re-acquisition | ENGAGING, RETURNING_TO_ORBIT |
| RETURNING_TO_ORBIT | Returning to orbit path | SCANNING, ABORTED |
| ABORTED | Critical failure | IDLE |

### Battery Thresholds

| Level | Range | Behavior |
|-------|-------|----------|
| Full | > 30% | Full protection, 5m engagement range |
| Close Range | 20-30% | 3m max engagement, conserve ammo |
| Orbit Only | 15-20% | Continue orbit, no engagement |
| Critical | < 15% | Force RTB immediately |

### Target Prioritization Scoring

```
score = YOLO_confidence × 10.0
      + (inbound? ? +50 : 0)
      + closest_bonus (up to +20)
```

## §2. 🟢 NEW: MotionCompensator Class

### Why Motion Compensation Is Mandatory

Without motion compensation, drone ego-motion (roll/pitch/yaw changes during flight) causes the CV pipeline to see targets "moving" even when they're stationary relative to the ground. This creates positive feedback oscillation in the turret servo loop, degrading aim stability.

### How It Works

```
IMU Gyro (ATTITUDE MAVLink msg)
  ├─ roll_deg, pitch_deg, yaw_deg
  └─ Delta from reference attitude
       └─ Rotation matrix R (Z-Y-X Euler)
            └─ Homography H = K @ R @ K_inv
                 ├─ stabilize_frame() → warped image
                 └─ stabilize_points() → compensated pixel coords
```

### Usage in CV Pipeline

```python
compensator = MotionCompensator(
    camera_matrix=camera_K,  # or auto-compute from FOV
    image_size=(640, 480),
    enable=True,
)

# Apply to frame:
stabilized = compensator.stabilize_frame(frame, roll, pitch, yaw)

# Apply to detection centers:
compensated_centers = compensator.stabilize_points(
    np.array([[cx, cy]]), roll, pitch, yaw
)
```

### Camera Matrix Default

Auto-computed from FOV if not provided:
- 70° HFOV, 50° VFOV, 640×480 → fx≈541, fy≈550

## §3. 🟢 UPDATED: Detector with YOLOv11 CoreML + LAB Colorspace

### Three Key Changes

1. **LABColorClassifier (NEW)**: CIELAB color space for team jersey identification. Decouples L* (lightness) from a*/b* (color). Uses CLAHE pre-processing for lighting normalization. Superior to HSV under variable outdoor lighting where H channel becomes unstable.

```
Team A (Red):    a* > 140, b* < 140
Team B (Blue):   a* < 130, b* < 120
```

2. **CoreML Backend**: Auto-detects `.mlpackage` file extension and routes to Apple Neural Engine. YOLOv11n achieves 110-130 FPS on MacBook M3 ANE (vs 50-60 FPS MPS GPU).

3. **Backend Selection**: Configurable via `backend` parameter:
   - `"auto"` — Detects `.mlpackage` → CoreML, else MPS
   - `"coreml"` — Force CoreML ANE
   - `"mps"` — Force Metal GPU
   - `"cpu"` — Force CPU

### YOLOv11n Deployment (MacBook M3)

```bash
# Setup
python3 -m venv yolo_env
source yolo_env/bin/activate
pip install ultralytics coremltools opencv-python

# Export to CoreML
python3 -c "
from ultralytics import YOLO
model = YOLO('yolo11n.pt')
model.export(format='coreml', nms=True, half=True, imgsz=640)
"

# Run with ANE
python3 splash/cv/main.py --coreml --no-preview
```

## §5. 🟢 UPDATED: MAVLink Bridge — SERVO_SET + DO_ORBIT

### New Commands

| Method | MAV_CMD | Purpose |
|--------|---------|---------|
| `set_servo(servo_num, pwm_us)` | 183 (DO_SET_SERVO) | Direct servo PWM control |
| `aim_servos(pan_deg, tilt_deg)` | 183 + angle→PWM conv | High-level pan/tilt |
| `do_orbit(lat, lon, radius, alt)` | 34 (DO_ORBIT) | Single-command orbit in GUIDED mode |
| `stop_orbit()` | Mode→GUIDED | Return to fly mode |

### Pan/Tilt Servo Configuration

```
Pan:  SERVO5_FUNCTION=6  (Mount Pan)  → PWM5 output
Tilt: SERVO6_FUNCTION=7  (Mount Tilt) → PWM6 output
```

Angle-to-PWM conversion: 0-180° → 1000-2000μs (90° = center = 1500μs)

## §7. RESEARCH FINDINGS

### TinyFish as arxiv Workaround

TinyFish search works as an arxiv paper discovery alternative when the arxiv API is rate-limited:
- `tinyfish search query "arxiv <topic>"` returns actual arxiv paper links with snippets
- Can then `tinyfish fetch content get` to read the abstract
- Or `web_extract` for full content

### Battery Selection Research

From TinyFish search and prior data:
- **GNB 850mAh LiHv**: ~80g, best capacity but struggles above 22A continuous
- **Tattu 650mAh LiPo**: ~72g, better discharge but lower capacity
- **Recommendation for Splash**: 4S 650mAh (Tattu/Equivalent at ~72g) for ~4min flight + 1min protection mode. GNBs 850mAh LiHv if weight allows (~80g)
- **Sub-250g reality**: With S18 pump (18g) + 10ml reservoir, AUW ~246g possible (under 250g) with careful component selection
