## §1. 🔴 CRITICAL: PUMP WEIGHT CORRECTION — Weighs 60g, Not 15g

### 1A. The Problem

Previous Splash research (multiple cycles) assumed the micro diaphragm pump weighed **15-25g**. Google AI Mode search on actual product listings reveals:

| Component | Previously Assumed | Actual Measured | Source |
|-----------|-------------------|-----------------|--------|
| 12V 370 Micro Diaphragm Pump (bare) | 15-25g | **60-66g** | Google AI Mode [1-6] |

| With silicone mounting sleeve | — | **72-75g** | Verified specs |
| 385 Micro Diaphragm Pump | 20-30g | **~110g** | Datasheet [5] |

**Impact:** The pump alone exceeds the entire 35g payload budget remaining for sub-250g.

### 1B. The Solution: Bodenflo/Hilintec S18 Series (18g)

| Parameter | S18 Micro Diaphragm | Notes |

| **Weight** | **18g** | Lightest self-priming diaphragm pump |
| **Mechanism** | Rotary coreless DC motor | No brushes, long life |
| **Voltage** | 12V DC | Compatible with 4S step-down or 3S |
| **Flow Rate** | 350-800 mL/min | Sufficient for water gun bursts |
| **Self-Priming** | Yes | Essential for drone use |

**Supplier:** Bodenflo (bodenpump.com), Hilintec (mini-pump.com)

**Alternative: Piezoelectric pump (Takasago SDMP, ~13g)** — Only 20-30 mL/min flow. Too slow for water gun use.

## §2. 🟢 MicoAir H743 v2 Complete UART Mapping

### 2A. UART-to-SERIAL Mapping

| SERIAL# | Hardware Port | Default Purpose | Splash Usage |
|---------|---------------|-----------------|--------------|
| SERIAL0 | USB | USB connection | Mission Planner / QGC (bench) |
| SERIAL1 | UART1 | Telemetry/MAVLink2 | Optional secondary telemetry |
| SERIAL2 | UART2 | DJI HD VTX (SH1.0 connector) | Not used (analog FPV) |
| **SERIAL3** | **UART3** | **GPS** | **GOKU GM10 GPS** |
| **SERIAL4** | **UART4** | **Secondary Telemetry** | **DroneBridge ESP32** |
| SERIAL5 | UART6 | RC Input (default) | ELRS Receiver |
| SERIAL6 | UART7 | ESC Telemetry (RX-only) | Not used |
| SERIAL7 | UART8 | General user peripheral | Servo control (PWM5/6) |

### 2B. Wiring Connections

**GPS (GOKU GM10 Nano V3):**
```
GPS TX → RX3 (FC pad)
GPS RX → TX3 (FC pad)
Compass SDA → SDA (FC I2C pad)
Compass SCL → SCL (FC I2C pad)
Power (5V) → 5V pad
Ground → GND pad
```

**RC Receiver (EP1 ELRS):**
```
RX TX6 → RX6 (FC pad)  [cross-connect]
RX RX6 → TX6 (FC pad)  [cross-connect]
Power → 5V pad
Ground → GND pad
```

**Servos (pan-tilt):**
- Pan: FC PWM5 output → MG90S signal wire
- Tilt: FC PWM6 output → MG90S signal wire
- Power: From 2S 300mAh payload battery (separate from flight battery)
- Config: SERVO5_FUNCTION=6 (Pan), SERVO6_FUNCTION=7 (Tilt)

| Parameter | Value | Description |
|-----------|-------|-------------|

| BRD_SER4_RTSCTS | 0 | Disable flow control |

## §3. 🟢 DroneBridge ESP32 — Wiring & Configuration

### 3A. Hardware Wiring

Connect DroneBridge ESP32 to MicoAir H743 **UART4** (SERIAL4):

| ESP32 Pin | FC Pin | Notes |
|-----------|--------|-------|
| 5V / VIN | 5V pad | FC BEC must supply 5V |
| GND | GND pad | Common ground |
| **RXD (GPIO16)** | **TX4 pad** | FC Transmit → ESP32 Receive |
| **TXD (GPIO17)** | **RX4 pad** | ESP32 Transmit → FC Receive |

**IMPORTANT:** Crossover wiring — TX of one goes to RX of the other.

### 3B. Software Configuration

**ArduPilot side:**
```
SERIAL4_PROTOCOL = 2    (MAVLink 2)
SERIAL4_BAUD = 115      (115200 baud)
BRD_SER4_RTSCTS = 0    (no flow control)
```

**DroneBridge side:**
1. Power on drone
2. Connect computer/phone to WiFi: "DroneBridge for ESP32" (password: `dronebridge`)
3. Open browser: `http://192.168.2.1` or `http://dronebridge.local`
4. Set UART protocol: MAVLink
5. Set UART baud: 115200
6. Save settings → Reboot

**GCS connection:**
- Connect to ESP32 WiFi network
- Open Mission Planner / QGroundControl
- Select **UDP** connection on port **14550**
- Bidirectional MAVLink established

### 3C. Field Operation

| Mode | Use Case | Configuration |
|------|----------|---------------|
| **Standard WiFi UDP** | Bench development | Higher throughput for video |
| **ESP-NOW Long Range** | Field ops | 1.2-3.5ms latency, 600m+ range, AES-256-GCM |
| **WiFi Long Range (LR)** | Extended range | 1.0-2.5km, lower throughput |

**For Splash field ops:** ESP-NOW mode recommended. Change DroneBridge config to ESP-NOW before flight.

## §4. 🟢 1505 3800KV Motor Performance Benchmarks

### 4A. Thrust Data (Per Motor, 4S 16.8V)

| Propeller | Max Thrust | Current @ Max | Efficiency (Cruise) | Best Use |
|-----------|-----------|---------------|-------------------|----------|
| HQProp T3.5x2x3 | **~540g** | **~16.5A** | 3.6 g/W | **All-around freestyle** |
| HQProp T3x3x3 | ~440g | ~14.2A | 4.2 g/W | Park flying |
| Gemfan 4024 (2-blade) | ~490g | ~13.0A | 5.4 g/W | Long range |

**Recommended prop for Splash:** HQProp T3.5x2x3 (3.5" tri-blade)
- Total thrust: **~2.1 kg** (4 motors) → thrust-to-weight ~8:1 at 250g AUW
- Peak current: **66A total** (MicoAir H743 v2 handles 45A × 4)
- Efficiency: 3.6 g/W at cruise → ~4-5 min flight time on 4S 650mAh

### 4B. Motor Specs

| Parameter | Value |
|-----------|-------|
| Motor Weight | 12.5-13.6g each |
| Max Power | 250-290W at 100% throttle |
| Peak Current | 15-18A per motor |
| Stator | 15mm × 5mm |
| Mount Pattern | 9mm M2 (compatible with Crux35 arms) |
| KV Options | 3400-4300KV (3800KV recommended for 4S) |

### 4C. PID Tuning Notes for 1505 Motors

- **P-gain**: Reduce by ~20% (higher inertia than 1404s)
- **D-gain**: Increase by ~15% (compensate for rotor spin-up delay)
- **Filter**: Lower D-term lowpass filter (e.g., `DTERM_LPF_TYPE=BIQUAD, DTERM_LPF_CUTOFF=120`)

## §5. 🟢 MacBook M3 CoreML YOLOv11 Deployment

### 5A. Step-by-Step Guide

```bash
# Step 1: Create environment
python3 -m venv yolo_env
source yolo_env/bin/activate

# Step 2: Install dependencies
pip install --upgrade pip
pip install ultralytics coremltools opencv-python

# Step 3: Export to CoreML (creates yolo11n.mlpackage)
python3 -c "
from ultralytics import YOLO
model = YOLO('yolo11n.pt')
model.export(format='coreml', nms=True, half=True, imgsz=640)
"

# Step 4: Run inference on M3 (auto-routes to ANE)
python3 -c "
from ultralytics import YOLO
import cv2
model = YOLO('yolo11n.mlpackage')
results = model('path/to/video.mp4', device='mps', stream=True)
for r in results:
    boxes = r.boxes.xyxy.cpu().numpy()
    confs = r.boxes.conf.cpu().numpy()
    cls = r.boxes.cls.cpu().numpy()
    # Process person detections (class 0)
    person_mask = cls == 0
    person_boxes = boxes[person_mask]
    person_confs = confs[person_mask]
"
```
