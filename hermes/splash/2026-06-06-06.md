**Gap:** Pipeline for red/blue team identification from drone altitude.

### Production Pipeline
```
[Drone Video Input] → YOLO Detection (person class only)
                           ↓ (Bounding boxes)

                           ↓
                    HSV Conversion (BGR→HSV)
                           ↓
                    Dual Red Mask (0-10° + 170-180°)
                    Blue Mask (90-130°)
                           ↓
                    Pixel Count → Team Classification
```

### Key HSV Calibration Values
```python
# Red wraps around 0° and 180° in OpenCV HSV
LOWER_RED1 = np.array([0, 70, 50])
UPPER_RED1 = np.array([10, 255, 255])
LOWER_RED2 = np.array([170, 70, 50])
UPPER_RED2 = np.array([180, 255, 255])
LOWER_BLUE = np.array([90, 50, 50])
UPPER_BLUE = np.array([130, 255, 255])
```

**Critical drone adaptations:**
1. **Vertical cropping:** Only upper 15-50% of bounding box (isolates jersey from green turf, shorts, socks)
2. **Keep S/V thresholds wide** (40-50 minimum) — drone lighting shifts rapidly
3. **CLAHE on V channel** before HSV conversion for lighting normalization
4. **Morphological opening** (`cv2.MORPH_OPEN`) to remove edge pixel bleed from grass/turf
5. Integrate with ByteTrack: `model.track(persist=True)` wraps YOLO detection in tracker → team identity persists across frames

**Splash use case:** In Senior Assassins, there's no formal team jersey system. Adaptation: detect target by clothing color description (e.g., "person wearing red hoodie") as a primary identification filter before lock-on.

### Splash Recommendation: **Geometric Height Scaling (no ML needed)**

For Splash specifically, the **simplest and most reliable** range method is:

```
Distance = (focal_length_pixels × average_human_height_meters) / bounding_box_height_pixels
```

Where `focal_length_pixels = (sensor_width_pixels × focal_length_mm) / sensor_width_mm`

- Hawkeye Thumb 4K camera specs known: 160° FOV, ~2.5mm focal length, 3840×2160 sensor

- No ML inference needed → zero frame rate impact on CV pipeline
- Calibration: measure bounding box at known distances, fit distance function
- **Accuracy:** ±10-20% sufficient for engagement threshold (2m = fire, >4m = wait)

**Fallback hybrid:** LiteDepth for general depth masking (detect if anything is close), geometric scaling for precise range.

## §6. 🟢 PCA9685 vs Direct ESP32 GPIO PWM (GAP RESOLVED)

**Gap:** Do we need PCA9685 for servo control?

### Verdict: **Direct ESP32 GPIO PWM is definitive for Splash**

| Attribute | PCA9685 (I2C) | Direct ESP32 LEDC PWM |
|-----------|---------------|----------------------|
| **Resolution** | 12-bit (4096 steps) | Up to **16-bit** (65535 steps) |
| **Jitter** | ±5-25µs (RC oscillator) | **<50ns** (crystal-locked) |
| **Latency** | 200-500µs per write (I2C) | **Instantaneous** (HW register) |
| **Pin count** | 2 pins for 16 servos | 1 pin per servo |
| **EMI risk** | I2C bus corruption from servo spikes | Low, isolated digital signals |
| **Weight** | ~2.5g extra | Zero (on ESP32 already) |
| **Cost** | ~$3 extra | Free |

**Splash only needs 2 servos** (pan + tilt). ESP32 has 16 PWM channels natively. PCA9685 adds:
- Unnecessary weight (2.5g)
- I2C bus contention with other peripherals
- Jitter from internal RC oscillator (±4% drift)
- 200-500µs latency cascade when updating both servos

**Circuit:**
- ESP32 GPIO18 → MG90S pan signal (PWM, 50Hz)
- ESP32 GPIO19 → MG90S tilt signal (PWM, 50Hz)
- MG90S power (red) → separate 6V BEC (not ESP32 3.3V rail!)
- MG90S GND → common ground

## §7. 🟢 ArduPilot Lua Protection Mode Script (GAP RESOLVED)

**Gap:** How to implement custom orbit + fire control logic via ArduPilot Lua.

### Complete Implementation

**Parameters to set:**
```
SCR_ENABLE = 1              # Enable Lua scripting engine
SERVO9_FUNCTION = -1        # Free Servo 9 for script control
FENCE_ACTION = 0            # Report-only (script handles geofence logic)
FENCE_ENABLE = 1            # Enable fence (for script to read)
```

**Script architecture (72 lines, from Google AI Mode research):**

The Lua script runs at 5Hz and implements:
1. **Target ingestion** — receives person coordinates from companion computer via MAVLink `VISION_POSITION_ESTIMATE` or `LANDMARK` messages
2. **Geofence check** — `fence:get_breaches()` or custom distance calculation from protected zone center
3. **Orbit activation** — `vehicle:start_orbit(target_location, 15.0, 5.0)` at 15m radius, 5 m/s
4. **Stabilization check** — waits until orbit_error = |dist - radius| ≤ 2m
5. **Fire control** — `SRV_Channels:set_output_pwm_chan(SERVO_FIRE_CH, 2000)` = fire, 1000 = safe
6. **Fallback** — target lost or fence breach → set RTL, disarm fire signal

**Splash adaptation notes:**
- Companion computer (MacBook) runs YOLO + ByteTrack CV pipeline
- Sends target GPS coordinates via ESP32 MAVLink bridge
- Script on FC handles orbit + fire logic independently
- Servo channel 9 mapped to IRL3705N MOSFET gate (pump relay)
- 1N4007 flyback diode on pump for back-EMF protection (already in design)
