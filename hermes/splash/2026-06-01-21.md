| Feature | Lucas-Kanade Optical Flow | Kalman Filter (Standard) | DeepSORT | ByteTrack (SOTA) |

### 1C. Team Jersey Identification — LAB Color Space (vs HSV)

**CRITICAL FINDING:** LAB (CIELAB) color space is **superior to HSV** for lighting invariance because it decouples lightness (L*) from color information (a*/b*). HSV's H channel becomes unstable when Value (brightness) or Saturation drops due to shadows.

**Implementation approach:**
1. **Pre-processing**: Apply CLAHE (Contrast Limited Adaptive Histogram Equalization) to luminance in YCrCb → convert to LAB
2. **Two-tier masking**: Otsu adaptive thresholding on a*/b* channels + static LAB range calibration
3. **Morphological cleanup**: MORPH_CLOSE (bridge gaps from jersey numbers/logos) + MORPH_OPEN (remove noise)
4. **Integration with YOLO**: Run YOLO person detection first, then crop bbox and apply LAB color filter on cropped region — adds only ~2ms

**LAB ranges for OpenCV** (8-bit mapping):
- **Red jersey**: a* > 145 (high redness), b* < 140 (neutral-to-warm)
- **Blue jersey**: a* < 130 (low redness), b* < 115 (high blueness)

### 1D. Monocular Depth Estimation for Range Finding

**Triangle similarity method** (zero CPU overhead):
```
Distance = (Known_Height × Focal_Length) / Pixel_Height
```

- Average human height: 1.7m
- Calibration needed: single known-distance measurement to compute focal length in pixels
- **Accuracy: ±0.5m at 5m range** — sufficient for fire/no-fire decision (threshold is typically 2-4m)
- **PnP fallback** (Perspective-n-Point): More accurate but needs camera calibration matrix

**For Splash:** Triangle similarity is sufficient. The 1m hysteresis zone (already in facts.json FACT-009) handles boundary cases.

### 1E. Motion Compensation (Ego-Motion Cancellation)

**Architecture confirmed** from existing FACT-002:
- Gyro deltas from ATTITUDE MAVLink messages → Rodrigues rotation matrix
- Camera homography: H = K @ R @ K_inv
- Stabilized pixel coordinates prevent turret oscillation during drone movement

**Implementation order:** ByteTrack person detection → motion compensation → Kalman smooth → servo PID → fire decision

### 2A. ArduPilot Orbit Waypoint Generation via Lua Scripting

ArduPilot's native Lua engine enables real-time mission generation using `DO_SET_CIRCLE` (MAV_CMD_20):

**Parameters:**
- Param 1: Radius (meters). Positive = clockwise, negative = counter-clockwise
- Param 2: Orbit speed (m/s). 0 = default loiter speed
- The orbit center is passed as latitude/longitude coordinates

**Required ArduPilot params:**
| Parameter | Value | Description |
|-----------|-------|-------------|
| SCR_ENABLE | 1 | Enable Lua scripting engine |
| SCR_HEAP_SIZE | 65536+ | Allocate memory for scripts |
| FENCE_ENABLE | 1 | Hardware geofence backup |
| FENCE_ACTION | 0 (Report Only) | Let Lua handle breach before hardware RTL |

**Lua script flow for protection mode:**
1. Wait for arm + AUTO mode
2. Clear current mission
3. Inject takeoff waypoint (MAV_CMD_NAV_WAYPOINT, target 20m alt)
4. Inject DO_SET_CIRCLE at protected player GPS coordinates
5. Continuously poll geofence breach status
6. On breach: set GUIDED mode → fly to nearest rally point
7. Return to orbit after engagement

**Alternative via MAVLink command** (simpler, from existing FACT-005):
```python
# pymavlink approach — no Lua needed for basic orbit
master.mav.command_long_send(
    target_system, target_component,
    MAV_CMD_DO_ORBIT, 0,  # command 34
    radius,          # param1: orbit radius (5-15m)
    speed,           # param2: orbit speed (2-5 m/s)
    0, 0, 0, 0,     # unused
    lat, lng         # orbit center
)
```

### 3B. ESP32-S3 WiFi Bridge — Latency Benchmarks

| Benchmark | Standard WiFi (UDP) | Standard WiFi (TCP) | ESP-NOW Mode | WiFi Long-Range (LR) |
|-----------|-------------------|-------------------|-------------|---------------------|
| **Average Latency** | 2.5-6 ms | 8-22 ms | **1.2-3.5 ms** | 5.0-12 ms |

**Recommendation for Splash:**

- **DroneBridge ESP32** firmware: Frame-alignment parser prevents MAVLink message fragmentation, injects native RADIO_STATUS MAVLink messages

## §4. 🟢 HOUR 6: WATER GUN HARDWARE — CLOSED

### 4A. Diaphragm vs Peristaltic — Definitive Comparison

| Metric | Micro Diaphragm (e.g., 12V 370/385) | Micro Peristaltic (Dosing Class) |
|--------|--------------------------------------|----------------------------------|
| Operating Pressure | **55-130 PSI** (3.8-9.0 bar) | Low **14-25 PSI** (1.0-1.7 bar) |
| Max Flow Rate | **5.0-8.0 L/min** | Very Low 0.03-0.4 L/min |
| Weight | **Light** (15-25g for micro class) | Heavy (145-765g) |
| Water Gun Range | **Long** (5-10+ m with matching nozzle) | None (gravity dribble) |
| Self-Priming | Yes (instant) | Yes (but slow) |
| Dry Running | Safe | Safe |

**Verdict: Diaphragm pump is the ONLY viable choice for Splash.** Peristaltic pumps are too heavy and produce insufficient pressure for any meaningful range.

### 4B. Pump Selection

**Confirmed from existing FACT-001:** 12V 370/385 micro diaphragm pump (15-25g, 0.8-1.5 L/min, 0.3-0.8 bar / 4-12 PSI, $5-8 AliExpress).

**CORRECTION from earlier research:** The claimed "20-30 PSI" on 030-series 3-5V pumps is dead-head pressure — actual delivery at useful flow is ~2 PSI (1.5m head), producing only 3-4 m/s stream velocity and ~1.5-2m range. The **12V 370/385** is the correct pump for Splash.

**Power circuit:**
- 12V pump: Direct from 4S battery via LM2596 step-down, OR separate 2S 300mAh payload battery
- MOSFET: IRFZ44N (logic-level gate, handles 2A+ with ease)
- Protection: 1000µF low-ESR capacitor + flyback diode across pump terminals
- Gate pull-down: 10kΩ to GND (prevents accidental firing during ESP32 boot)

### 4C. Nozzle Design — Maximum Range Parameters

**Optimal design for Splash:**

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| **Orifice diameter** | 3.0-4.5 mm | Smaller = too much backpressure; larger = too heavy water column |
| **Contraction cone** | 12-15° included angle | Gentle taper prevents boundary layer separation |
| **Laminar flow matrix** | Honeycomb grid, 15-20mm length | Eliminates pump-induced vortices before nozzle |
| **Straight discharge tip** | Length = 2× orifice diameter | Stabilizes exit vector |
| **Material** | PETG (not PLA) | Water resistance + 4+ bar pressure tolerance |

**Range vs Pressure (ideal, at 45° elevation):**
| Pressure | Ideal Max Range | Real-World Breakup Distance |
|----------|----------------|---------------------------|
| 2.0 bar (29 PSI) | 20.4 m | **11.5-13.0 m** |
| 4.0 bar (58 PSI) | 40.8 m | **16.0-19.5 m** |
| 6.0 bar (87 PSI) | 61.2 m | **21.0-24.5 m** |

**Real-world expectation:** With the 12V 370/385 pump at 4-12 PSI (0.3-0.8 bar), Splash achieves **2-4m effective range** before stream breakup. This is sufficient for Senior Assassins engagement distances (3-5m typical).

**3D Printing Settings:**
- **PETG filament** (NOT PLA — degrades under water)
- **Vertical orientation** (standing on base)
- **0.1-0.12 mm layer height**
- **6-8 perimeters** (solid walls, no infill)
- **100% concentric infill**
- **Flow rate 103-105%** for watertight layers
- **Post-process**: Sand interior with 1000-2000 grit wet paper, coat with thin epoxy

### 4D. Servo Pinch Valve (from existing FACT-002)

MG90S metal gear servo + 3D-printed eccentric cam + 4-5mm ID × 7-8mm OD silicone tube. Confirmed at ~10g total — exponentially lighter than motorized ball valve (50g+).

### 5B. Critical Failure Modes — Lessons Learned

**1. Power Supply Brownouts (The Motor Spike)**
- Inductive pump load causes ESP32 brownout → flight controller freeze
- **Solution**: Independent power paths + 1000µF capacitor + flyback diode + optocoupler isolation

**2. CG Slosh During Maneuver**
- Water shifts violently in half-empty tanks → erratic PID corrections
- **Solution**: Medical IV bag (flexible bladder, no slosh) OR 3D-printed internal baffles

**3. WiFi Latency vs Flight Control**
- High-res video streaming saturates ESP32 bandwidth → 500ms+ latency
- **Solution**: Drop to QVGA 320×240 @ 13-15 FPS for CV stream. **Failsafe**: Land/hover if keep-alive signal lost for >1.5s

**4. Boot-Up Accidental Firing**
- ESP32 GPIO pins default to HIGH during boot → pump fires unexpectedly
- **Solution**: Use boot-stable GPIO pins (4, 12, 14) with external 10kΩ pull-down resistors

**5. Drone Recoil from Water Jet (from existing FACT-001)**
- Newtonian reaction torque destabilizes yaw
- **Solution**: ArduPilot counter-yaw mixer rule (RCx_OPTION) proportional to pump PWM

### 5C. Closest Open-Source Reference

**jonathanrandall/electric_watergun_with_tracking** on GitHub:
- ESP32-CAM → WiFi stream → Python YOLO → UDP servo commands (port 8085)
- Proven at 640×480
- Proportional-only control (Kp only) — Splash's full PID+Kalman is more sophisticated
- **Adapt for Splash**: Replace raw PWM with MAVLink SERVO_SET commands
