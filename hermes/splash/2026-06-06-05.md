## §2. 🟢 Computer Vision & Tracking (HOUR 2)

### YOLOv11n vs YOLOv8n Benchmark

| Metric | YOLOv8n | YOLOv11n |
|--------|---------|----------|
| Parameters | 3.2M | 2.6M (-22%) |
| GFLOPs (@640×640) | 8.7 | 6.5 |
| CoreML FP16 FPS (M3) | ~90-110 | ~100-120 |
| PyTorch MPS FPS (M3) | ~45-60 | ~40-50 |
| Small-object recall | Good | Superior (C3k2 + C2PSA) |
| Drone edge viability | High | Very High |
| Post-processing | Redundant boxes | Cleaner, less redundant |

**Key insight:** CoreML export (`.mlpackage` FP16) routes through Apple Neural Engine (ANE), doubling FPS vs PyTorch MPS. Export: `yolo export model=yolov11n.pt format=coreml half=True`. YOLOv11n is the definitive choice for Splash.

### TrackingPanTiltCam (maxboels/TrackingPanTiltCam)

- **GitHub:** 3 stars, Python, last push Sep 2025
- **Architecture:** OpenCV → YOLOv8 → Kalman filter → serial → Arduino → servos
- **Two modes:**
  - *Surveillance Mode*: Long history buffer (10 frames), high smoothing, gradual weight — for monitoring
  - *Turret Mode*: Short buffer (3 frames), exponential weighting, low smoothing — **for auto-aim** ← Splash target
- **Motion compensation:** Feedback loop filter prevents camera motion from confusing vision algorithm
- **Kalman filter:** Predicts target position between frames, smooths through occlusions

**Fork potential:** Directly adaptable for Splash. Replace USB camera with ESP32-CAM stream. Replace Arduino with ESP32 (already onboard). Replace servos with MG90S pan-tilt.

### Gaps Identified
- **HSV color filtering for team jerseys:** Not in TrackingPanTiltCam. Need to add OpenCV HSV mask pipeline for red/blue team identification.
- **Multi-person tracking:** TrackingPanTiltCam tracks single person. Need ByteTrack or BoT-SORT for Splash multi-target.
- **Depth estimation:** Monocular depth (MiDaS/DPT) or ultrasonic sensor needed for range-to-target calculation.
- **Optical flow:** Lucas-Kanade for motion prediction when target is momentarily occluded.

## §3. 🟢 Auto-Aim & Ballistics (HOUR 3)

### Water Stream Trajectory Physics

**Nozzle exit velocity:** v0 = Q / A (where Q = flow rate, A = nozzle area)

**Nozzle pressure (Bernoulli):** Pnozzle = 0.5 × ρ × (v0 / Cd)²
- ρ = 1000 kg/m³ (water)
- Cd = 0.98 (efficient smooth nozzle)

**Total system pressure:** Ppump = Pnozzle + ΔPfriction + ΔPelevation

**Maximum theoretical range (vacuum):** R = v0² × sin(2θ) / g (θ = 45° optimal)

**Real-world range:** Droplet drag atomizes stream → rapid deceleration. Firefighter Blair's formula: Reffective ≈ 0.05 × Pnozzle (psi) + constant.

**Key tradeoff:** Smaller nozzle → higher velocity but atomizes faster. 1.5-2mm orifice is the sweet spot for micro pumps.

### Servo PID for Pan-Tilt
- From TrackingPanTiltCam: P-control loop sending angle corrections via serial to Arduino
- MG90S at 6V: 2.2 kg·cm torque, 0.10s/60° — adequate for water nozzle
- PCA9685: 16-channel I2C servo controller — optional if FC has enough PWM outputs
- **Splash approach:** ESP32 GPIO PWM (16 channels available on ESP32) → MG90S directly. No PCA9685 needed.

### Firing Logic
- **Distance threshold:** Fire when target bounding box area > X% of frame (implies within range)
- **Confidence threshold:** Fire only when YOLO detection confidence > 0.7
- **Lock duration:** Fire after 0.5s continuous lock (prevents false positives from fleeting detections)
- **Lead calculation:** For moving targets: lead_angle = atan2(target_velocity, stream_velocity) — requires frame-to-frame velocity estimation

## §4. 🟢 Protection Mode (HOUR 4)

System: **ArduPilot Orbit + Geofence + Companion Computer CV**

### ArduPilot Configuration

| Parameter | Value | Purpose |
|-----------|-------|---------|
| `FENCE_ENABLE` | 1 | Enable geofence engine |
| `FENCE_TYPE` | 7 | Alt + Circle + Polygon |
| `FENCE_ACTION` | 1 | RTL on breach |
| `FENCE_MARGIN` | 2.0 | 2m buffer zone |
| `CIRCLE_RADIUS` | 50 (or custom) | Orbit radius in meters |
| `CIRCLE_RATE` | 20 (or custom) | Orbit speed in °/sec |
| `FENCE_AUTOENABLE` | 1 | Auto-activate after takeoff |

### Protection Mode State Machine
```
IDLE → ARM → TAKEOFF → ORBIT(center, radius, alt)
         ↑                      ↓
         |               DETECT(person inside geo?)
         |                    /           \
         |                 YES            NO (continue orbit)
         |                  ↓
         |          TRACK + AIM (CV pipeline)
         |                  ↓
         |              FIRE(pump relay ON)
         |                  ↓
         |     RETARGET? → YES → TRACK
         |                  ↓ NO
         └──────── ORBIT ← RETURN to orbit waypoint
        
BATTERY < 20% → RTL at any point
```

### Key Design Decisions Needed
1. **How to define "protected area"** — GPS waypoint circle vs geofence polygon?
2. **Person detection trigger** — Companion computer CV (YOLO on MacBook via ESP32 video stream) vs onboard ESP32-CAM detection?
3. **Return-to-orbit logic** — After firing, navigate back to orbit center via waypoint command
4. **Target prioritization** — Closest approach first, or all sequentially?

**Recommended approach:** Geofence polygon for the protected zone. Companion computer (MacBook) runs YOLO + tracking. Sends `MAV_CMD_NAV_LOITER_UNLIM` or custom Lua script for orbit pattern. Firing triggers via MAVLink `DO_DIGICAM_CONTROL` mapped to pump relay.

## §5. 🟢 Phone Control & ESP32 Bridge (HOUR 5)

### ESP32-S3 MAVLink WiFi Bridge

**Wiring:**
- ESP32 TX → FC RX (UART6/TELEM2)
- ESP32 RX → FC TX (UART6/TELEM2)
- ESP32 GND → FC GND
- ESP32 VIN → FC 5V rail

**FC Configuration:**
- `SERIAL6_PROTOCOL` = 2 (MAVLink 2)
- `SERIAL6_BAUD` = 115 (115200)

**ESP32 Firmware Logic:**
1. WiFi: Access Point mode (SSID: `Splash_Link`) or connect to existing network
2. UDP: Open socket on port 14550
3. Serial→UDP: Read `Serial.read()` bytes, send as UDP packet
4. UDP→Serial: Listen for incoming UDP, write to `Serial.write()`

**Key principle:** Treat MAVLink as raw bytes — NO parsing on ESP32 minimizes latency and memory.

**QGC on Phone:**
1. Connect phone to ESP32 WiFi
2. QGC → Application Settings → Comm Links → Add UDP → Port 14550 → Connect

**MCP Tool Mapping (LLM Control):**

| MCP Command | MAVLink Equivalent |
|-------------|-------------------|
| `arm()` | `MAV_CMD_COMPONENT_ARM_DISARM` |
| `takeoff(alt)` | `MAV_CMD_NAV_TAKEOFF` |
| `orbit(center, radius, alt)` | `MAV_CMD_DO_ORBIT` + `MAV_CMD_NAV_LOITER_UNLIM` |
| `identify_target(description)` | (Companion computer: YOLO class filter) |
| `track_and_fire()` | CV pipeline + `DO_DIGICAM_CONTROL` |
| `protect_mode(area, duration)` | Geofence + orbit + CV trigger loop |
| `rtb()` | `MAV_CMD_NAV_RETURN_TO_LAUNCH` |

## §6. 🟢 Water Gun Hardware (HOUR 6)

### Pump Selection

| Pump Type | Weight | Flow Rate | Pressure | Range | Verdict |
|-----------|--------|-----------|----------|-------|---------|
| Peristaltic micro | 15-25g | 100-300 mL/min | Low (0.1-0.3 bar) | ~0.5m | ❌ Too slow, low pressure |
| Coreless gear pump | **12-15g** | 400-600 mL/min | Low-Med | ~1-1.5m | ⚠️ Best for sub-250g, test range |
| R385 micro diaphragm | 60-65g | 500-800 mL/min | Med (2-6 bar) | ~2-4m | ✅ Best range, heavy (exceeds sub-250g) |
| 370 diaphragm | 60-66g | ~300 mL/min | Med (3-5 bar) | ~2-3m | ✅ Documented in prior cycles |
| 385 diaphragm | ~110g | ~1 L/min | High (6-8 bar) | ~5m+ | ❌ Too heavy for 250g limit |

**Decision:** Coreless gear pump (12-15g, 400-600 mL/min) for strict sub-250g build. R385 or 370 for >250g build with better range.

### Servo Pan-Tilt

| Servo | Weight | Gears | Bearing | Torque @ 6V | Verdict |
|-------|--------|-------|---------|-------------|---------|
| SG90 | 9g | Plastic | Bushing | 1.8 kg·cm | ❌ Will strip under recoil |
| MG90S | **13g** | Metal | Ball bearing | **2.2 kg·cm** | ✅ Definitive choice |
| MG996R | 55g | Metal | Dual ball | 10 kg·cm | ❌ Overkill for sub-250g |

**Decision:** 2× MG90S at 6V via separate BEC (~3g). Optional PCA9685 if more servo channels needed.

### MOSFET Firing Circuit

**Critical correction from prior research:** IRFZ44N requires Vgs ≥ 10V — FC 3.3V/5V GPIO cannot saturate it fully, causing overheating.

**Correct spec:** IRL3705N or IRLZ44N (logic-level MOSFET, saturates at 3.3-5V Vgs)

**Circuit:**
```
FC GPIO → 220Ω resistor → IRL3705N Gate
                           IRL3705N Gate → 10kΩ pulldown → GND
                           IRL3705N Drain → Pump (-) terminal
                           IRL3705N Source → GND
Pump (+) → 1N4007 flyback diode (cathode @ Pump +)
           1N4007 (anode) → Pump (-)
Pump (+) → FC 12V rail (via relay/switch)
```

### Nozzle Design
- **Geometry:** 15° convergent angle → 1.5-2mm straight land (4mm length)
- **Material:** PETG or ABS, 100% infill, 0.12mm layer height
- **Post-processing:** Epoxy resin coating inside to seal micro-pores + reduce surface friction
- **Mount:** 3D-printed adapter to MG90S pan-tilt

### Reservoir
- **Winner:** Flexible IV bag or TPU 3D-printed bladder (1-2g dry)
- **Capacity:** 15mL → ~3-9 short bursts or ~3-5 protection-mode engagements
- **Benefits over rigid:** Zero slosh (bag collapses), no CG shift, lightweight
- **Mount:** Magnetic quick-release + Luer-lock connector
