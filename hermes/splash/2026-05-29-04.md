## 1. 🟡 QGroundControl Custom Widget Architecture

### 1.1 Plugin Architecture Overview

QGC uses a **CustomPlugin** pattern built on `QGCCorePlugin`. The entry point for custom QML is the **`CustomOptions`** class which overrides `QGCOptions`. This provides URL overrides for every major UI component.

**Key QGCOptions Overrides for Splash:**
```cpp
class CustomOptions : public QGCOptions {
public:
    QUrl  mainToolbarUrl()     const final { return QUrl::fromUserInput("qrc:/custom/SplashMainToolBar.qml"); }
    QUrl  planToolbarUrl()     const final { return QUrl::fromUserInput("qrc:/custom/SplashMainToolBar.qml"); }
    QUrl  flyViewOverlay()     const final { return QUrl::fromUserInput("qrc:/custom/SplashFlyOverlay.qml"); }
    QUrl  preFlightChecklistUrl() const final { return QUrl::fromUserInput("qrc:/custom/SplashPreFlight.qml"); }
    CustomInstrumentWidget* instrumentWidget() final { return nullptr; } // Use our own
};
```

### 1.2 Three Fly View Customization Layers

| Layer | File | Complexity | Splash Strategy |
|-------|------|-----------|-----------------|
| **Base** | `FlyView.qml` | High — map + video switching + guided controls | Do NOT override unless absolutely necessary |
| **Widgets** | `FlyViewWidgetsOverlay.qml` | Medium — all remaining controls | Override to add Splash-specific buttons (Auto-Track, Protect, Fire) |
| **Custom** | `FlyViewCustomLayer.qml` | Low — additive overlay | **RECOMMENDED** — use for Splash HUD: target lock indicator, ammo count, orbit status |

**Recommendation for Splash:** Start with `FlyViewCustomLayer.qml` + `QGCOptions::flyViewOverlay()`. Only escalate to Widgets override if buttons need to replace/suppress upstream controls.

## 2. 🔴 MCP Server Architecture — Splash Drone Control Tools

### 2.1 Two Reference Implementations

| Aspect | **ion-g-ion/MAVLinkMCP** | **Google AI Mode Example** |
|--------|--------------------------|---------------------------|
| GitHub | [MAVLinkMCP](https://github.com/ion-g-ion/MAVLinkMCP) | Concept from arXiv 2601.15486v2 |

| Transport | UDP (`udp://:{port}`) | UDP (`udpin:localhost:14540`) |

| Target | PX4 (MAVSDK-centric) | ArduPilot (uses MAV_CMD directly) |

**Splash Decision:** Use **pymavlink-based approach** (Google example pattern) because:
1. ArduPilot primary target (not PX4)
2. Direct MAV_CMD control (MAV_CMD_DO_ORBIT, etc.)
3. No MAVSDK dependency — lighter weight
4. Compatible with existing research on MAV_CMD_DO_ORBIT from HOUR 4

## 3. 🔴 ESP32 WiFi Bridge — Communication Layer

### 3.1 Implementation Comparison

| Feature | **Custom UDP Passthrough** | **DroneBridge for ESP32** | **mavesp32** |
|---------|---------------------------|---------------------------|-------------|
| Latency | **1.2 – 3.5 ms** | 5 – 12 ms (ESP-NOW) | 8 – 15 ms |
| Range | ~150m (WiFi) | **1km+ (ESP-NOW)** | ~100-150m |
| Encryption | None (raw) | **AES-GCM 256-bit** | None |
| Weight | ~5g (ESP32-S3 board) | **<8g** (official HW) | ~5g |
| Config | Manual code | **Web interface** | Manual code |
| Setup | Complex | **Simple (web flasher)** | Moderate |
| Multiprotocol | MAVLink only | MAVLink, MSP, LTM, transparent | MAVLink only |
| Packet handling | Blind passthrough | Smart parsing + routing | MAVLink framing |

### 3.2 Recommendation: DroneBridge for ESP32

**WHY:**
- Web-based flashing tool at drone-bridge.com/flasher — zero-toolchain setup
- Official hardware: JST-GH 6-pin connector → direct plug into FC TELEM port
- ESP-NOW mode: 1km range, encrypted, connectionless (no WiFi handshake overhead)
- QGC/Mission Planner auto-detection
- Three operating modes: Standard WiFi (150m), ESP-NOW (1km), Drone Light Show
- **<8g weight** — critical for sub-250g budget

### 3.5 Latency Budget for Splash

```
FC UART TX → ESP32 DMA buffer:    ~0.1 ms
ESP32 processing (Core 1 UART):   ~0.5 ms
LwIP UDP stack (Core 0 WiFi):     ~0.8 ms
Air propagation (WiFi 2.4GHz):    ~1.0 ms
MacBook WiFi stack → pymavlink:   ~1.0 ms
─────────────────────────────────────────
Total estimated link latency:     ~3.4 ms
```

**Splash Implication:** At 3.4ms round-trip, target tracking at 30 FPS (33ms frame interval) has ~10x headroom. CV inference dominates latency, not MAVLink.

### 4.1 Splash State Machine

```
                    ┌────────┐
                    │  IDLE  │ ← Disarmed, on ground
                    └───┬────┘
                        │ arm()
                    ┌───▼────┐
                    │ ARMED  │
                    └───┬────┘
                        │ takeoff(alt)
                    ┌───▼────────────────────────────┐
                    │         AIRBORNE               │
                    │  ┌────────────────────────┐    │
                    │  │     ORBIT              │◄───┤ protect_mode()
                    │  │  (loiter/hover)         │    │
                    │  └───────┬────────────────┘    │
                    │          │ detect target        │
                    │  ┌───────▼────────────────┐    │
                    │  │     DETECT             │    │
                    │  │  (CV person detection)  │    │
                    │  └───────┬────────────────┘    │
                    │          │ target confirmed     │
                    │  ┌───────▼────────────────┐    │
                    │  │     TRACK              │    │
                    │  │  (CV tracking lock)     │    │
                    │  └───────┬────────────────┘    │
                    │          │ in range, locked     │
                    │  ┌───────▼────────────────┐    │
                    │  │     AIM                │    │
                    │  │  (servo pan-tilt)       │    │
                    │  └───────┬────────────────┘    │
                    │          │ firing solution OK   │
                    │  ┌───────▼────────────────┐    │
                    │  │     FIRE               │    │
                    │  │  (pump activate)        │    │
                    │  └───────┬────────────────┘    │
                    │          │ burst complete       │
                    │  ┌───────▼────────────────┐    │
                    │  │     RETURN             │    │
                    │  │  → ORBIT or → RTB      │    │
                    │  └────────────────────────┘    │
                    │                                │
                    │  ANY STATE ──── rtb() ────────►│
                    └────────────┬───────────────────┘
                                 │ land / rtb complete
                    ┌────────────▼──────┐
                    │      IDLE         │
                    └───────────────────┘
```

### 4.2 Python State Machine Implementation

```python
from enum import Enum, auto
import asyncio

class SplashState(Enum):
    IDLE = auto()
    ARMED = auto()
    TAKING_OFF = auto()
    ORBIT = auto()
    DETECT = auto()
    TRACK = auto()
    AIM = auto()
    FIRE = auto()
    RETURN = auto()
    EMERGENCY = auto()

class SplashStateMachine:
    def __init__(self, mav_conn):
        self.state = SplashState.IDLE
        self.master = mav_conn
        self.target_locked = False
        self.ammo_remaining = 15  # shots
        self.battery_pct = 100

    VALID_TRANSITIONS = {
        SplashState.IDLE:      [SplashState.ARMED],
        SplashState.ARMED:     [SplashState.TAKING_OFF, SplashState.IDLE, SplashState.EMERGENCY],
        SplashState.TAKING_OFF:[SplashState.ORBIT, SplashState.EMERGENCY],
        SplashState.ORBIT:     [SplashState.DETECT, SplashState.RETURN, SplashState.EMERGENCY],
        SplashState.DETECT:    [SplashState.TRACK, SplashState.ORBIT, SplashState.EMERGENCY],
        SplashState.TRACK:     [SplashState.AIM, SplashState.ORBIT, SplashState.EMERGENCY],
        SplashState.AIM:       [SplashState.FIRE, SplashState.TRACK, SplashState.EMERGENCY],
        SplashState.FIRE:      [SplashState.RETURN, SplashState.TRACK, SplashState.EMERGENCY],
        SplashState.RETURN:    [SplashState.ORBIT, SplashState.IDLE, SplashState.EMERGENCY],
        SplashState.EMERGENCY: [SplashState.IDLE],
    }

    def transition(self, new_state: SplashState) -> bool:
        if new_state in self.VALID_TRANSITIONS.get(self.state, []):
            # Battery check on upward transitions
            if self.battery_pct < 15 and new_state not in [SplashState.IDLE, SplashState.RETURN, SplashState.EMERGENCY]:
                print(f"Battery {self.battery_pct}% — forcing RETURN")
                self.state = SplashState.RETURN
                return False
            self.state = new_state
            return True
        return False

    # Battery-aware guard
    def check_battery(self):
        if self.battery_pct < 15:
            self.transition(SplashState.RETURN)
            return "RTB_LOW_BATTERY"
        elif self.battery_pct < 20 and self.state in [SplashState.AIM, SplashState.FIRE]:
            return "LOW_BATTERY_WARNING"
        return "OK"
```

## 5. 🔴 Safety Systems — Failsafe Configuration

### 5.1 Complete Safety Parameter Table for Splash (4S LiPo)

| Parameter | Splash Value | Description |
|-----------|-------------|-------------|
| **BATT_LOW_VOLT** | `13.6` | Low battery threshold (3.4V/cell × 4S) |
| **BATT_LOW_TIMER** | `10` | Seconds voltage must be low before trigger |
| **BATT_FS_LOW_ACT** | `2` | Action on low batt: **RTL** |
| **BATT_CRT_VOLT** | `12.8` | Critical battery (3.2V/cell) |
| **BATT_FS_CRT_ACT** | `1` | Action on critical: **Land immediately** |
| **FENCE_ENABLE** | `1` | Enable geofence |
| **FENCE_TYPE** | `3` | Altitude + Circle (1+2=3) |
| **FENCE_ACTION** | `1` | Breach action: **RTL or Land** |
| **FENCE_RADIUS** | `1500` | 150m geofence radius (cm) |
| **FENCE_ALT_MAX** | `3000` | 30m altitude ceiling (cm) |
| **FENCE_MARGIN** | `200` | 2m margin before trigger |
| **FS_GCS_ENABLE** | `1` | GCS link loss: **Always RTL** |
| **FS_GCS_TIMEOUT** | `5` | 5s heartbeat loss before trigger |
| **FS_THR_ENABLE** | `3` | RC failsafe: **Land** (ELRS handles signal) |
| **FS_THR_VALUE** | `970` | PWM threshold for RC loss |
| **FS_OPTIONS** | `0` | No override on failsafe behavior |

### 5.2 Kill Switch Configuration

```
RCx_OPTION = 66    # Maps channel X to "Motor Emergency Stop"
                   # Cuts ALL PWM to ESCs immediately
                   # Drone FALLS — use only for terminal emergencies
```

### 5.3 Lost-Link Behavior (Splash-Specific)

For Splash, the drone operates autonomously via WiFi (no direct RC control during mission). Therefore:
- **FS_GCS_ENABLE=1** is CRITICAL — if MacBook WiFi drops, drone RTBs
- **FS_GCS_TIMEOUT=5** — 5 seconds is enough to survive brief WiFi hiccups
- **FS_OPTIONS bit 1** should remain 0 — we do NOT want the drone continuing auto-mission if GCS link is lost (unlike survey drones)

### 5.4 Pre-Flight Safety Checklist

1. Verify **FENCE_ENABLE=1** and **FENCE_RADIUS** set for field
2. Confirm **BATT_LOW_VOLT** matches battery cell count
3. Test **RC kill switch** (RCx_OPTION=66) works in SITL
4. Verify **FS_GCS_ENABLE=1** triggers RTL on WiFi disconnect
5. Set **ARMING_CHECK=1** (all pre-arm checks enabled)
6. Confirm GPS lock ≥ 8 satellites before arming (GPS_HDOP < 1.5)

## 7. Key Decisions & Blockers

### Decisions Made This Cycle:
1. **MCP Server: pymavlink, not MAVSDK** — ArduPilot-native, direct MAV_CMD control
2. **ESP32 Bridge: DroneBridge (official HW)** — <8g, web-flashed, ESP-NOW 1km range
3. **QGC: `FlyViewCustomLayer.qml` first** — additive overlay, low maintenance cost
4. **State Machine: Python `Enum`-based** — explicit valid transitions, battery-aware
5. **GCS Link Loss: Always RTL (FS_GCS_ENABLE=1)** — safety-first for autonomous ops

### Blockers:
- **NONE** — HOUR 5 is software/integration. No hardware dependencies blocking.
- **Pre-req:** Frame switch decision (carbon tube vs Volador) from HOUR 1 research needed before final wiring diagram
