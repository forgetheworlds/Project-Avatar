## §2. 🟢 Pratik Phadte — LLM-Controlled Drone (Local Ollama)

**Source:** YouTube (19K views) + GitHub pratikPhadte/LLM-controlled-drone

**Tech Stack:** Ollama (local LLM) + ROS2 + YOLOv8 + PX4 + Gazebo SITL

**Three-Tier Architecture:**
1. **ROS2 Brain Node**: Collects telemetry (GPS, NED, battery), packages with user prompt → Ollama
2. **Ollama (Local LLM)**: Returns structured JSON `{"action": "orbit", "lat": 47.39, "lon": 8.54, "alt": 40, "radius": 20}`
3. **Command Translator Node**: Validates JSON against rigid flight behaviors before sending to PX4 via uXRCE-DDS/MAVLink

**Key Insight for Splash:** The **Command Translator is a safety firewall** between LLM and flight controller. It validates JSON structure, parameter ranges, and state safety before execution. **Splash MCP server should adopt this pattern** — validate tool parameters against ArduPilot limits (e.g., altitude ceiling, battery level) before sending MAV_CMD.

**Supported Actions:** takeoff, goto, orbit, square, land, rtl — all enforced as rigid JSON schemas.

**Available Models Tested:** Qwen2.5, Llama-3.2, Gemma3 — all successful with system-prompt-constrained JSON output.

**Splash Decision:** ADOS could replace QGC custom widget effort. Altnautica has a live demo at command.altnautica.com with 5 simulated drones. **Recommendation:** Evaluate ADOS plugin sandbox as alternative to QGC custom build for Splash phone control UI.

## §5. 🟢 ESP32 WiFi Bridge Latency — Confirmed Architecture Valid

**Source:** Google AI Mode (ESP32 MAVLink UDP bridge research)

**Optimized Architecture:**
```
[ ArduPilot FC ] ── UART ──> [ ESP32 Bridge ] ── UDP WiFi ──> [ MacBook M3 / Phone ]
                                  │
                              <3ms latency
```

**Critical Latency Settings:**
- `esp_wifi_set_ps(WIFI_PS_NONE)` — Disable power saving → ping from 100ms to <3ms
- Fixed UDP packet buffer (263 bytes MAVLink frame) — immediate flush, no timeout wait
- ESP32 does NOT handle video — passes through to companion computer

**For Splash CV Pipeline:**
- ESP32 handles MAVLink bridge at <3ms
- Hawkeye Thumb 4K → USB-C → MacBook M3 for CV processing
- MacBook → MAVLink commands → ESP32 (UDP) → FC UART → servos/pump
- **Benchmark from May 31 confirmed:** 1080p UVC stream via USB (Hawkeye direct to MacBook) has <50ms total pipeline latency with YOLO26n at 90-95 FPS

**Phone Integration:**
- Phone connects to ESP32 WiFi AP
- QGC or ADOS Mission Control opens UDP comm link on port 14550
- Video source: RTSP or UDP H.264 stream from MacBook M3
- For Manual Mode: Phone runs QGC → ESP32 UDP:14550 → FC UART
